# 测量报告：上下文压缩的成本构成

本报告记录 2718Labs 对 DeepSeek Harness 上下文压缩成本的测量结果。测量对象为官方压缩后端（`@deepseek-ai/dsh-compaction-basic`），测量目的为确定压缩成本的构成，并据此设计本插件。原始数据可从会话日志重新计算，工具位于 [`bench/`](../bench/README.md)。

## 摘要

| 观测项 | 实测值 |
| --- | --- |
| 样本 | 25 个会话、3,515 次请求、997,002,631 prompt token |
| 稳态前缀缓存命中率 | 99.20% |
| 官方后端单次自动压缩的额外输入 | 约 72 万 token（摘要调用约 55 万，发布重读约 17 万） |
| 压缩前最近一次请求的缓存状态 | 命中 99.93% / 99.85% / 99.07%，距压缩 12.8 秒 / 0.1 秒 / 1.1 秒 |
| 摘要请求的缓存命中 | 0 至 9,856 个 token |

上述缓存行为源于重放请求与实际发送请求之间的差异：请求期组装的内容不在会话日志中，重放无法复现。该约束适用于任何基于重放的摘要实现，不构成官方后端的功能缺陷。

- 本插件的 `deterministic` 模式不进行模型调用，可跳过约 55 万 token 的重读；`extract` 模式调用一次模型，成本与官方后端基本持平。
- 同一会话三次自动压缩合计，占该会话输入成本约 5.3%；若使用 `deterministic` 模式，可降至约 1.2%。
- 工具结果剪枝在同一会话中释放 141,041 token，导致后续请求多读 1,675,192 token。

## 1. 目的与范围

测量回答三个问题：

1. 长会话的输入成本由什么构成；
2. 官方压缩的额外成本落在哪一步；
3. 是否存在不降低压缩质量的替代路径。

测量只覆盖桌面版 Harness 的会话日志，不涉及模型输出质量的主观评价。质量部分以契约测试与证书机制描述，见第 7 节。

## 2. 数据与方法

- 数据来源：Harness 持久化的会话日志（`session*.jsonl.zstd`，格式版本 v2 至 v4）。
- 读取范围：`assistant/message` 事件的 usage 记录、`compaction/start`、`compaction/summary`、`compaction/end`、`compaction/prune` 标记事件。不读取消息内容；摘要仅取其字符长度用于估算发布尺寸。
- 会话标识：取会话目录名的 SHA-256 前 8 位，报告中以 `s-xxxxxxxx` 标注。该标识在同一台机器上稳定，跨机器不可比。
- 成本单位：未命中等价输入 token（`miss-equivalent`），计算式为 `未命中输入 + 0.1 × 缓存读取`。0.1 为价格假设，对应 provider 公布的缓存读取折扣，可用 `--hit-ratio` 调整。
- 压缩成本的定义：对每个 `compaction/start` 至 `compaction/end` 的区间，取区间前最近一次请求与区间后第一次请求。摘要调用的用量记于 `compaction/summary` 事件；发布成本取区间后第一次请求的未命中输入。
- 剪枝成本的定义：连续 `compaction/prune` 标记归为一轮，取其前最近一次请求与轮内最后一条标记之后的第一次请求。若该轮与下一次压缩相邻，则无法归因，标记为排除。
- 运行环境：DeepSeek Harness `0.2.1-rc.5` 桌面版；provider `deepseek-account`，模型 `deepseek-flash`。

## 4. 自动压缩成本

同一会话（s-3e456bb3）内的三次自动压缩：

| turn | 压缩前 prompt | 摘要调用（缓存 / 未命中 / 输出） | 压缩后 prompt | 发布未命中 | 合计 miss-equivalent | 占该会话输入 |
| --- | --- | --- | --- | --- | --- | --- |
| 22 | 726,882 | 0 / 552,771 / 4,124 | 189,833 | 179,977 | 733,734 | 1.77% |
| 47 | 724,803 | 9,856 / 562,954 / 5,059 | 171,536 | 161,680 | 726,605 | 1.76% |
| 83 | 729,572 | 9,856 / 549,132 / 3,206 | 180,230 | 170,374 | 721,477 | 1.74% |

三次合计 2,181,816 miss-equivalent，占该会话输入成本的 5.27%。其中发布成本 512,031 未命中 token 属于任何改写历史的方案都必须支付的代价；摘要调用的 1,666,828 miss-equivalent 是本节关注的可控部分。

## 5. 归因分析

为排除缓存过期，检查了每次压缩之前最近一次请求的状态：

| turn | 距压缩前一次请求 | 该请求的命中率 |
| --- | --- | --- |
| 22 | 12.8 秒 | 99.93% |
| 47 | 0.1 秒 | 99.85% |
| 83 | 1.1 秒 | 99.07% |

缓存处于有效状态。摘要请求只命中 0 至 9,856 个 token，说明其前缀自 9,856 个 token 之后与之前请求不一致。

进一步验证：压缩时重放的 durable surface 投影与运行时投影一致（自检输出 `live=399 replayed=399 identical=true`）。因此分歧不在持久日志的重建方式，而在**线上请求**：实际发出的请求包含请求期组装、未写入日志的内容，重放无法复现。

结论：对任何基于重放的摘要实现，摘要调用无法复用压缩前的缓存，成本接近一次完整 prompt 读取。该约束同时适用于官方后端与本插件的 `extract` 模式，不构成官方后端的功能缺陷；官方后端的其余流程（事务、锁、溢出恢复、保留尾部、重放）在本插件中保持原样。

## 6. 模式对照

| 模式 | 模型调用 | 每次自动压缩的额外输入 | 相对官方 | 发布内容 |
| --- | --- | --- | --- | --- |
| 官方摘要 | 1 次，重读约 55 万 | 约 72 万 | 1× | 模型撰写的摘要，无出处 |
| 本插件 `extract` | 1 次，同等重读 | 约 72 万 | ≈1× | 逐字引文 + 结构证书 |
| 本插件 `deterministic` | 无 | 约 17 万 | ≈0.25× | 结构筛选后的原文片段 |

`deterministic` 的发布尺寸与官方摘要存在差异，上表按同量级估算。该模式的代价是缺少语义抽取，压缩质量低于 `extract`。

## 7. 发布内容的质量约束

成本之外，本插件对发布内容设定了可测试的约束：

| 约束 | 官方摘要 | 本插件 |
| --- | --- | --- |
| 关键约束丢失的可检测性 | 无 | 约束与锚点固定为支座，丢失时拒绝发布（有测试覆盖） |
| 内容可回溯性 | 无 | 每条要求逐字引用原文，无法定位则丢弃 |
| 压缩失败时的行为 | 抛出错误，可能无 checkpoint | 结构编译 → 本地渲染 → 官方摘要三级降级 |
| 渲染确定性 | 依赖模型 | 相同输入逐字节一致 |

官方摘要的实测长度为 1,728 至 5,131 token。本插件 checkpoint 受 `checkpointMaxTokens` 约束（默认 6,000），且只包含可核验内容。

离线测试共 80 条断言，覆盖：伪造与转述引文的拒绝、支座丢失的拒绝、无法接地结构的报错、不可缩小源的拒绝、抽取失败时的降级、`deterministic` 模式不调用模型、渲染的逐字节一致性。

## 9. 不确定性与局限

- 三次自动压缩均来自同一个长会话。单次事件为实测数据，样本量有限，跨会话外推属于推断。
- `extract` 模式的成本持平为结构性论证（相同重放、相同发布），不是同一会话的 A/B 对照。压缩对单个会话是单向操作，无法直接 A/B。
- 价格假设（缓存读取按未命中 10% 计）可调，但会影响报告中所有折算数值。
- 摘要请求与线上请求的具体分歧点由测量推断，未直接获取线上请求体；日志不记录该请求期内容。
- 让抽取调用复用缓存的前提是取得与线上请求逐字节一致的请求体，目前未实现。

## 附录：字段定义

- **摘要调用**：`compaction/summary` 事件记录的模型用量，含缓存读取、未命中输入与输出 token。
- **发布未命中**：`compaction/end` 之后第一次请求的未命中输入。任何改写历史的方案都需支付。
- **合计 miss-equivalent**：摘要调用与发布的未命中等价输入之和。
- **占该会话输入**：合计 miss-equivalent 除以该会话全部请求的 miss-equivalent。
- **占用 token 数**：`compaction/prune` 事件中 `shadowedTokenCount` 的累计值。
